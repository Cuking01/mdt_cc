# 编译优化路线

本文档记录当前编译器的优化状态。状态标记如下：

- `[已完成]`：已经进入默认编译流程，并有测试或实际示例验证。
- `[基础设施]`：相关 IR 或分析能力已经具备，但优化规则尚未完整启用。
- `[计划中]`：尚未实现。
- `[暂不做]`：当前收益不足或需要更完整的运行时模型。

## 总览

| 优化方向 | 状态 | 预期收益 | 主要难点 |
| --- | --- | ---: | --- |

| 基本块与后继分析 | `[基础设施]` | — | 动态函数返回边尚未完整建模 |
| 未调用函数消除 | `[已完成]` | 中 | 全局初始化也必须作为可达性根 |
| 常量折叠 | `[部分完成]` | 中 | 当前主要依赖赋值传播 |
| 基本块内赋值折叠 | `[已完成]` | 高 | 需要正确识别定义和使用 |
| 无意义赋值消除 | `[已完成]` | 中 | 函数调用和动态返回需要保守处理 |

## 已完成部分

### IR

编译器先生成线性 IR，再降低为 MDT 汇编。IR 已经支持：

- 独立的操作节点和标签节点；
- 操作数角色：定义、值、标签、元数据；
- 基本块边界和静态后继分析；
- 副作用与终结指令识别；
- 精确的最终指令计数。

标签不占用最终指令，因此 IR 下标和 MDT 指令序号是两个不同概念。

### 未调用函数消除

从 `main_loop` 和全局初始化表达式建立可达函数集合。只生成可达函数，未使用函数不会占用 1000 条指令限制。

全局初始化是独立的执行阶段，因此以下函数也必须保留：

```cpp
int initialize() { return 7; }
int value = initialize();
```

### 基本块内赋值折叠

当前已实现：

```text
set a b
set c a
```

传播为：

```text
set a b
set c b
```

同时支持：

- 自赋值删除；
- 复制来源传播；
- 常量来源传播；
- 基本块内活跃性分析；
- 删除无后续用途的 `set`、`op`、`read` 和 `getlink` 定义。

`write`、打印、绘图、flush、wait 和 `set @counter` 被视为副作用，不会被删除。

## 自动内联

当前函数调用包含参数复制、返回地址设置、跳转、返回值复制等固定开销，小函数尤其浪费指令。自动内联以调用图的被调用者优先顺序处理函数，并在调用关系改变后重新考虑尚未内联的函数。

收益不使用静态公式估算，而是对整个 IR 进行试变换：

1. 复制当前 IR；
2. 在副本中内联候选函数的所有调用点；
3. 为每个调用点重命名函数体内的标签；
4. 将所有动态返回改写为跳到该调用点的返回标签；
5. 删除候选函数的原始函数体；
6. 重新执行赋值传播和死赋值消除；
7. 只有最终操作指令数严格减少时才接受副本。

因此参数复制、返回值复制、多个 `return`、跨基本块控制流以及优化后暴露出的死赋值都会自然计入最终收益。函数有多个调用点时，所有调用点和删除函数体的收益作为一个整体判断；当前不会为了运行性能而接受代码长度不变或增长的内联。

当前语言禁止直接和间接递归，因此同一函数的参数槽、结果槽和局部存储可以由顺序执行的内联副本复用；函数体内部标签仍必须按调用点独立重命名。

`examples/rotate_line.mdtc` 在仅有赋值优化时为 277 条指令，启用自动内联并将赋值优化运行到稳定点后为 204 条，进一步减少 73 条（约 26.4%）。

## 内存地址优化计划

数组访问当前可能生成：

```text
op mul row_offset row stride
op add row_address offset row_offset
op add address row_address column
read value handle address
```

后续可以引入结构化地址表达式：

```text
handle + base + index * scale + constant_offset
```

可实现的优化包括：

- 常量偏移合并；
- `scale == 1` 时删除乘法；
- 相同数组行的基地址复用；
- 连续访问时地址递增；
- `sizeof(T)` 为常量时进行强度削弱。

暂不缓存 `read` 结果。`write` 会改变内存状态，且 Mindustry 运行时可能存在外部状态变化，未完成别名分析前不能跨内存副作用复用读取结果。

## 推荐实施顺序

1. `[计划中]` 跳转穿透与不可达基本块删除；
2. `[计划中]` 条件跳转简化；
3. `[计划中]` 结构化内存地址表达式；
4. `[计划中]` 基本块内公共子表达式消除；
5. `[暂不做]` 跨内存访问的读取缓存和复杂循环优化。
